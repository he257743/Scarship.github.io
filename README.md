# 创造之域 Scarship

受经典体素沙盒玩法启发的原创浏览器游戏。Three.js 渲染，像素材质由程序生成，没有使用 Minecraft 的贴图、音效或代码。

当前版本为 **3.0.0 山川聚落版**，提供 512 × 512 大地图、雪山河湖、村庄部落、村民交易，以及创造、生存、挖掘建造、基础合成与本地存档。它不是 Minecraft 官方产品，也没有实现原版的全部系统。

- [游戏入口](https://he257743.github.io/Scarship.github.io/)：仓库开启 GitHub Pages 后可访问。
- [源码仓库](https://github.com/he257743/Scarship.github.io)
- 推荐使用支持 WebGL 与 Pointer Lock 的桌面版 Chrome 或 Edge。手机提供触屏控制，性能取决于设备。

## 启动

在项目目录运行：

```sh
python3 -m http.server 8080
```

然后访问 http://localhost:8080 。代码使用 ES Modules，需要通过 HTTP 服务访问，不要直接双击 index.html。没有构建步骤、API Key 或后端依赖。Three.js 已附在 vendor 中，首次下载项目后可离线运行。直接提交静态文件即可在 GitHub Pages 使用。

完整下载与启动示例：

```sh
git clone https://github.com/he257743/Scarship.github.io.git
cd Scarship.github.io
python3 -m http.server 8080 --bind 127.0.0.1
```

只试玩需要 Python 3 和浏览器，不必安装 npm 依赖。也可以在装有 Node.js 和 Python 3 时运行 `npm start`。关闭提供 HTTP 服务的终端会停止本地服务。

## 第一次进入世界

1. 填写世界种子，相同种子生成相同的初始地形。
2. 选择创造或生存模式，点击“创建新世界”。已有存档时可选择“继续上次的世界”。
3. 桌面浏览器会锁定鼠标。按 Esc 释放鼠标并暂停，点击“回到世界”继续。
4. 创造模式按 E 打开目录；先点击要更换的快捷栏格子，再点击要装入的物品。
5. 生存模式从砍树开始，按下方流程制作工作台和工具。长按左键挖掘，而非只点击一下。

手机左侧圆盘移动，拖动画面观察；右侧有跳跃、挖掘、放置、背包和暂停按钮。

## 已实现

- 可复现的种子世界，512 × 512 水平范围，96 格高度，可探索面积为旧地图的约 28.4 倍；草地、沙地、深层石头、基岩、洞穴、煤铁钻石矿、橡树、桦树、植物与仙人掌。
- 连绵山地、积雪山顶、蜿蜒河流、低地湖、高山湖、固定瀑布和三座跨河木桥。
- 七座具名聚落：溪谷村、松岭部落、沙丘聚落、白桦村、山麓村、远湾村、南原部落；包含四栋可进入的住宅、水井、道路、灯柱、床铺、工作台与灌溉农田。
- 每座聚落五名村民，有农夫、木匠、石匠、牧人、旅商的名称与服装。白天沿村内路线活动，夜间往住宅移动；右键可按统一基础交易表兑换面包和绿宝石。
- 按 M 打开世界地图，查看玩家、聚落、山水地标，标记路线与距离；创造模式可前往目的地或观景点，生存模式保留步行探索。
- 分块可见面合并渲染，随玩家位置加载与卸载附近区块，最多保留 9 × 9 个渲染区块；像素材质图集、方向明暗、透明玻璃、水和镂空树叶。
- 第一人称视角，玩家体积碰撞、重力、跳跃、疾跑、潜行防掉落、游泳；创造模式飞行。
- 六格触及距离、方块描边、持续挖掘、裂纹与进度、碎屑、放置防卡入自身、中键选取；手臂、手持方块和动作。
- 九格快捷栏、滚轮选取、创造物品目录、生存资源数量、配方列表、工作台距离要求、木镐与石镐及木斧木锹、工具耐久。
- 生存生命、饥饿、苹果进食、摔落和溺水伤害、死亡重生。生存模式死亡保留背包。
- 12 分钟昼夜周期、太阳月亮星空、移动方块云，猪牛羊漫游，程序生成的基础操作音效。
- 标题、暂停、背包菜单，视野与声音设置，F3 调试信息，触屏移动/观察/跳跃/挖掘/放置按钮。
- 每 20 秒及离开页面时本地存档，继续游戏、JSON 导入导出，存档字段与范围检查。

## 探索山川与聚落

新世界从溪谷村附近出生。按 M 选择村庄或地标，再点击“标记路线”，游戏画面会显示目的地与剩余距离。创造模式多一个“前往此地”按钮，山水地标会使用岸边或山侧观景点，避免直接落到湖底。创造飞行速度已提高，便于探索大地图。

村民交谈距离为六格以内，墙体会阻挡交互射线。基础交易包括 6 根橡木原木换 2 个面包、8 份成熟小麦换 3 个面包、12 份圆石换 1 颗绿宝石、1 颗绿宝石换 8 个面包。生存交易会检查并扣除资源，创造交易不消耗资源。

农田中的成熟小麦可直接采收，用于交易；尚无重新播种与生长周期。房屋预留开放的两格高入口，尚未实现可开关的门。村民使用简化的村内路线和避障，玩家改建道路可能使其绕行或停留。

## 存档

浏览器 localStorage 保存一个世界，创建新世界会替换该槽位。不同浏览器、不同网址和端口不共享存档。清除浏览器数据会删除本地世界；暂停菜单可导出 JSON 作备份。只保存世界种子与编辑差异，不把整个地形写入存储。动物、村民的实时位置和临时地图标记不保存，重新加载后重新生成；交易得到的物品和采收、改建的方块会保存。

暂停菜单中的“保存世界”可以立即写入；“导出世界存档”下载 `scarship-world.json`；“导入世界存档”恢复该格式的文件。新存档格式版本为 `3`，保存生成器版本 `generation`，导入上限为 20 MB。存档只在本机保存，不上传 GitHub 或其他服务器。

兼容 2.0.0 的版本 2 存档：保留原来 96 × 96 区域的初始地形和玩家编辑，在外围扩展新地形、六座聚落与山水。旧地形与外围之间有过渡带。继续旧世界即可探索扩展区域，按 M 查找外围村庄；要体验从溪谷村起步的七聚落布局，请先导出旧存档，再创建新世界。迁移后保存为格式 3，并保留 `generation: 2`，之后仍使用兼容地形。

## GitHub Pages 部署

1. 将本项目的静态文件提交到仓库 `main` 分支根目录。
2. 在仓库 **Settings → Pages → Build and deployment** 中选择 **Deploy from a branch**。
3. 选择 **main** 分支、**/ (root)** 目录并保存。
4. 等待 Pages 部署完成，访问上方游戏入口。后续推送到 `main` 后由 GitHub Pages 更新。

所有资源都使用相对路径，可部署在仓库子路径下。不需要服务端、环境变量、数据库或打包构建。如果仓库已使用自定义 GitHub Actions 部署，保留现有配置并检查其是否将根目录这些静态文件发布到 Pages。

根目录附有 `.nojekyll`，用于按普通静态站点发布。`node_modules/`、测试截图和本地存档文件都不需要上传到部署产物。

## 项目结构

```text
index.html                 页面、HUD 与各个菜单
style.css                  桌面和触屏布局
world.js                   种子地形、方块定义、碰撞、射线和配方
graphics.js                材质图集、区块网格、天空、动物与第一人称显示
game.js                    游戏状态、输入、物理、合成、存档与主循环
exploration.js             世界地图、地标导航与村民交易菜单
vendor/three.min.js        本地 Three.js r128
vendor/THREE-LICENSE.txt   Three.js MIT 许可证
tests/world.test.js        逻辑单元测试
tests/browser-smoke.cjs    浏览器交互测试
```

地形以字节数组存储，水平按 16 × 16 划分 1024 个区块，只生成可见面；编辑方块时重建受影响的已加载区块。渲染器仅保留玩家附近最多 81 个区块，移动时释放远处网格并逐帧补建新区块。未加载区域的编辑仍保存在世界数据中，返回时重新建模。基础体素数组约 24 MiB；地形数据一次生成，按需加载的是渲染网格，而非无限地形生成。单个世界最多 512 × 512 × 96 格。

## 验证

单元测试需要 Node.js 20 或更新版本，无需安装依赖：

```sh
npm test
```

浏览器集成测试需要 Playwright、Google Chrome 和运行在 8080 的 HTTP 服务。安装开发依赖：

```sh
npm ci
```

在一个终端中启动 `npm start`，另一个终端中运行：

```sh
npm run test:browser
```

测试默认使用本机 Chrome 的无头模式，不需要下载 Playwright Chromium。如果没有 Chrome，请先安装 Google Chrome。默认访问 `http://127.0.0.1:8080`，可以通过环境变量 `SCARSHIP_BASE_URL` 指定其他测试服务地址。截图写入 `test-results/`，该目录不会提交到 Git。

浏览器测试使用隔离上下文，在测试拦截的模块中注入检查入口；正式游戏没有测试入口。覆盖鼠标挖掘/放置、移动、背包选择、存档刷新恢复、配方材料消耗、工作台要求，以及大地图导航、地标传送、区块数量上限和扣除资源的村民交易。单元测试另检查山水结构、村庄入口、瀑布水柱和旧生成器地形的 SHA-256 一致性。桌面窗口缩为手机宽度的检查不等于真实手机 GPU 和多点触摸的全面验证。

## 常见问题

**打开后黑屏或提示初始化失败**：通过 HTTP 或 HTTPS 打开，检查浏览器是否启用 WebGL、硬件加速，以及 `vendor/three.min.js` 是否完整。静态文件必须保持目录结构。

**鼠标无法观察方向**：先点击“创建新世界”或“回到世界”以锁定鼠标。部分内嵌预览限制 Pointer Lock，改用独立浏览器标签页打开本地或在线地址。

**推送后页面还是旧版**：先确认 GitHub Pages 已部署对应提交，再强制刷新浏览器。推送成功和 Pages 部署成功是两个不同步骤。

**找不到之前的存档**：确认访问的浏览器、域名、协议和端口与之前一致。`localhost` 与 `127.0.0.1` 属于不同来源，彼此不共享存档。

**工具配方无法点击**：检查资源数量，工具还要求玩家在放置的工作台附近。物品不必放在快捷栏里才能作为合成材料。

**树叶或玻璃附近帧率降低**：透明表面和大量方块编辑会增加渲染负担。关闭其他占用 GPU 的页面，使用桌面浏览器；当前没有完整图形质量调节系统。

**离线运行的含义**：项目文件保存在本机、启动本地 HTTP 服务后，游戏运行不依赖外部网络。尚未实现 Service Worker/PWA，单纯访问过在线版不保证下次离线仍能打开。

## 当前边界

这是可玩的增强版，不是 Minecraft 全量实现。世界仍为有限区域；没有无限地形生成、红石、熔炉冶炼、液体传播、沙砾下落、门和楼梯形状、敌对生物、动物战斗/繁殖、维度、附魔、多人联网或完整的原版合成表。河湖瀑布为固定水体，不进行动态流体模拟。村民尚无职业独占配方、声望、繁殖、袭击与完整寻路系统。合成是配方列表而非原版九宫格，物品按类型累计，不模拟所有独立堆叠槽。矿物暂不按镐的等级限制掉落。

优先后续方向：地形分块生成、完整照明传播、熔炉与容器、更多方块形状、独立物品堆叠、实体战斗与掉落，然后再接红石或多人同步。

Three.js r128 的 MIT 许可证见 vendor/THREE-LICENSE.txt。
